> **Windows 预览实现：** 本分支新增 [Windows 版源码、启动及打包说明](windows/README.zh-CN.md)。它使用重新实现的主机控制层与原生架构 Linux 容器，和下方介绍的原版 macOS 安装包分别维护。

Egress Workbench 是面向 macOS 的**指纹运行环境**，为 Claude Code、Codex 和共享 Chromium 提供统一的网络出口、时区配置与持久化工作空间。

工具运行在 Linux 环境中，可以读写你在 Mac 上选定的项目目录。普通停止和重启会保留软件、登录与会话状态，让你继续处理已有项目。

目前实现的是出口 IP 与估计地区核对、时区配置，以及工具和浏览器状态的持久化。Linux、容器和硬件特征仍可能被识别；它不是物理机模拟器，也不保证匿名、防封或账号被服务商接受。其他工具需要单独确认兼容性。

**配置一次，之后直接在终端工作。** 不同项目使用各自的工作目录，已支持的工具共用账号授权。

## 能做什么

- **持久化工作工具：** 完整安装包内包含 Claude Code、Codex 和 Chromium。节点订阅和工具账号由你提供。
- **固定联网路径：** 环境自行连接你选择的节点。节点不可用时，不会自动退回普通网络。
- **连接由你确认：** 先查看实测出口 IP、估计地区和时区，再启用环境。检测到节点或出口变化后，需要重新检查并确认。
- **操作真实项目文件：** 从 Mac 项目目录运行命令，即可将它共享给对应的 Linux 工作环境。多个项目可以同时使用。
- **一个共享浏览器：** 所有项目共用 Cookie、书签和历史。登录使用这个浏览器，Mac 浏览器只负责显示远程画面。
- **中英文界面：** 首次跟随 macOS 语言，可在设置中手动更改语言和外观。应用与 Mac 端自有提示支持中英文；Linux 内部少量启动诊断和第三方工具输出仍保留英文。

## 使用前准备

需要一台运行 **macOS 14 或更新版本的 Apple Silicon Mac**、已启动的 **Docker Desktop**、足以容纳 Linux 环境的磁盘空间，以及支持的连接节点。当前使用 Docker Desktop 的 `desktop-linux` 环境；OrbStack、Colima 可以被识别，但暂不支持作为运行引擎。

0.3.3 支持固定公网 IPv4 节点：**Trojan TCP/TLS、VMess AEAD TCP（可带 TLS）、VLESS TCP/TLS，以及无插件的 Shadowsocks AEAD/2022 TCP**。已有订阅链接、URI/Base64、Clash `proxies` 和 EWB 节点配置继续兼容。不支持的传输或选项会说明原因，不会暗中降级连接方式。

也可以直接粘贴或选择单个 Trojan 客户端 JSON，需包含 `type`、`host`、`port`、`password` 等字段。可选的 `data` 地址不会被访问或保存，`udp` 标志不会开启 UDP。其他协议的单对象客户端 JSON 暂不支持。

**还需要开启本机 VPN 吗？** Egress Workbench 会自行连接所选节点。本机 VPN 不需要选择同一节点，也不要求开启 TUN 模式；但 Mac 必须能够访问该节点的服务器。应用控制的是这套工作环境的流量，不是整台 Mac 的全部流量。

**尽量固定使用可信、适合长期使用的稳定节点。** 频繁更换网络或地区，可能触发额外账号验证；例如，[OpenAI 将异常登录位置列为可能触发安全提示的原因之一](https://help.openai.com/en/articles/10471992-why-am-i-receiving-a-suspicious-activity-alert)。同一节点也不保证出口 IP 永远不变，任何节点都不能保证账号被服务商接受。Egress Workbench 检测到出口变化后，会要求重新检查并确认。

## 第一次使用

1. **安装应用。** 打开 DMG，将 Egress Workbench 拖到“应用程序”，启动 Docker Desktop，再打开 Egress Workbench。按 macOS 的正常流程批准打开预览版，不要全局关闭系统安全保护。
2. **确认数据目录。** 可以保留默认位置，也可以选择外接硬盘上的专用文件夹。先确认位置，再导入环境。
3. **导入安装包中的环境。** 应用会在本机校验并导入内置组件，不再分别下载 Claude Code、Codex 和 Chromium。等待完成；失败时会保留已有数据，可在同一目录重试。
4. **导入并选择节点。** 粘贴订阅或节点链接，或选择配置文件，然后选中支持的节点并点击“检查”。检查节点会停止这套环境中正在运行的工作，应用会先请你确认。订阅只在本机解析。部分提供商使用证书兼容设置，可能需要确认信任该订阅；你无需手动提供证书文件或填写指纹。
5. **核对出口。** 查看出口 IP、估计地区和时区，点击“核对并确认”。看到“已确认可用”后，再开始使用。
6. **按需登录工具。** 打开“账号”，选择 Claude Code 或 Codex。终端会显示进度。请在**共享浏览器远程画面内的官方页面**完成授权，不要把授权链接复制到外层 Mac 浏览器地址栏。
   可以先跳过账号步骤，稍后再登录。完成设置引导不代表账号已登录。
7. **在终端打开项目。** 按“连接”页的示例运行。应用显示的命令会指向当前数据目录，避免电脑上已有另一套环境时误用旧命令。

### 数据放在哪里？

有三个不同的位置：

| 位置 | 保存的内容 |
|---|---|
| 应用程序目录 | macOS 应用本身 |
| 你选择的数据目录 | 私有节点设置、主机端运行文件、日志和浏览器下载 |
| Docker Desktop 数据盘 | Linux 镜像、容器、工具的持久化用户目录、登录、会话和浏览器配置 |

项目文件仍保存在原来的 Mac 文件夹中。**选择外接硬盘作为数据目录，不会自动移动 Docker 数据盘。** 如有需要，请在 Docker Desktop 中单独设置其位置。迁移到另一台电脑，需要另外备份和恢复所选目录及 Docker 中的数据。上面的首次使用步骤用于新建环境；只复制应用或所选目录不等于完整备份。应用或 Docker 正在使用外接盘时，不要直接拔盘。

备份或迁移时，请保留上述两个数据位置。当前桌面预览版没有内置迁移向导。

### Docker 镜像存储兼容性

自 0.2.8 起，安装包为 containerd 和 classic 两种镜像存储提供完整的离线镜像集合，并识别它们不同的镜像标识。**安装本版本无需切换镜像存储。** 安装器不会更改 Docker 存储设置、覆盖已有镜像标签，或删除已有容器与数据卷。导入后会核对全部三个所需镜像；校验失败时停止安装，不会暗中转为在线下载。

0.2.8 已在 Docker Desktop Engine 29.4.3 的 classic 存储和隔离 ARM64 Engine 29.9.2 的 containerd 存储上完成原生离线安装、重复安装及数据保留检查。containerd 测试中，已有测试容器、可写层、镜像标签和卷内数据均保持。该结果不代表覆盖所有 Docker 版本；0.2.8 尚未重做全新 Mac 上 Docker Desktop 4.97 图形界面的冷安装验收。

## 日常使用

“设置 > 检查环境”按需读取本地配置及已创建容器的隔离、挂载状态，不会启动工作负载或探测公网；未验证的项目会明确标出。

应用无法确认 `ewb` 短命令入口时，会显示完整命令路径。**请用应用显示的路径替换下文中的 `ewb`。** 可以在“设置”中添加 `~/.local/bin/ewb` 入口；应用不会修改 Shell 配置。如果终端找不到 `ewb`，仍可使用完整路径。

```sh
cd /path/to/your-project

# 打开交互界面
ewb claude
ewb codex

# 直接发送一个问题
ewb claude -p "Summarize this project"
ewb codex exec "Summarize this project"

# 继续已有会话
ewb claude --continue
ewb codex resume

# 进入当前项目的 Linux Shell
ewb shell
```

把示例项目路径替换为自己的目录。工具会修改共享的真实文件，仍需做好版本管理和备份。项目内容可能包含个人或业务信息，应用不会自动清除或改写这些内容。

### 更新订阅或更换节点

订阅每月更新时，打开 **连接 > 连接设置**，粘贴新的订阅地址或选择下载好的文件，点击 **解析导入**。选择节点后点击 **检查**，核对出口信息并确认，再继续使用。这是手动更新，不会删除已经安装的软件、项目、账号、会话或浏览器配置，也不需要重新安装 DMG。

检查节点前请先保存工作，因为这会停止本环境的工作进程。已建立浏览器或项目后，如新节点需要改变国家、城市或时区，应用会保留原环境并提示使用新专用目录，不会自动搬迁已有身份数据。

### 更新已有环境

**从 0.3.0–0.3.2 更新到 0.3.3：** 替换 App 即可。如果“设置”提供运行组件更新入口，请先完成更新，再检查并确认连接。已有数据仍保存在原数据目录中；macOS 仍可能要求批准打开更新后的应用。

替换 App 后，在“设置”查看运行组件状态，并使用提供的更新入口。0.2.7 → 0.2.9 已通过升级测试，原有授权、配置、项目登记、容器可写层和持久化卷保留，旧运行组件会备份。只替换 App 不会自动更新已安装的运行组件。已完成初始化的 0.2.6 保护版也保留备份升级路径。更新前请先结束活动会话。成功后环境保持停止，需要重新检查并确认连接。尚未初始化的旧目录会提示先完成连接设置；更旧或不兼容的目录会提示使用新专用目录，原数据保留。恢复未完成时，保持 Docker 运行并使用“继续恢复”。

### 账号登录

```sh
ewb claude auth login     # Claude Code
ewb login                 # Codex
```

上述命令使用共享的内部浏览器。内部登录流程失败时会停止，不会回退到 Mac 浏览器打开账号页面。浏览器会保留 Cookie，但服务商可能让会话过期或要求重新验证身份。**账号状态未知不等于已经退出登录。** 普通重启环境不会主动清除授权。

在 **账号 > 刷新账号状态** 中，可以通过官方 CLI 接口检查已保存的本地授权。检查不会发送模型请求，也不会向界面返回凭据内容。

| 显示 | 含义 |
|---|---|
| 绿色：已登录 · 本地授权 | 工具识别到了本地授权。 |
| 黄色：尚未登录 | 没有检测到本地授权。 |
| 蓝色：正在检查 | 检查仍在进行中。 |
| 灰色：暂时无法检查 / 历史结果 · 请刷新确认 | 查看原因后刷新，不代表已经退出登录。 |

本地授权存在不保证服务商接受下一次请求；会话过期或被撤销时，仍可能需要重新登录。正常更新环境会保留已有授权。

### 浏览器和剪贴板

```sh
ewb browser
ewb browser stop
```

无论从哪个目录启动，都是同一个共享浏览器。用 **Paste in** 将 Mac 文字传入。复制回来时，先在 Chromium 内选中文字，按 **Ctrl+C**，再点击 **Copy out**。只有点击时才写入剪贴板，不会自动同步，支持中文、英文和多行文本。下载文件位于数据目录下的 `browser-files/Downloads`。

关闭显示页不会停止 Chromium。`ewb browser stop` 可以释放浏览器资源，并保留配置和下载。

### 网络检测网站

先打开共享浏览器，再点击应用“浏览器”页的 **Net.Coffee** 或 **fuck-claude.app**，也可以使用远程显示页顶部的 **Network checks · 网络检测** 菜单。两个固定入口分别打开 [ip.net.coffee/claude](https://ip.net.coffee/claude/) 和 [fuck-claude.app](https://fuck-claude.app/)，网页在 Chromium 新标签中使用环境已确认的连接访问。

首次提示可以跳过，不会自动访问网站。Egress Workbench 不读取或解析检测结果，由网站自行展示；网站的判断也不保证账号一定能被服务商接受。

### 查看与释放资源

```sh
ewb ps             # 查看运行中的容器和资源使用
ewb stop           # 停止当前项目
ewb stop-all       # 停止这套环境，包括公共服务
```

所有会话、Shell 和后台任务退出后，项目容器**空闲 30 分钟**会自动停止。等待输入的工具仍算活跃。浏览器和公共服务不参与自动停止。停止不会清除软件、授权或会话文件。

## 连接状态说明

| 状态 | 应该做什么 |
|---|---|
| 尚未完成设置 | 到“开始使用”页完成步骤。 |
| 正在检查连接 | 等待检查结果后再开始工作。 |
| 已确认可用 | 可以启动工具或浏览器。 |
| 等待你的确认 | 核对检测结果，再确认使用该节点和出口。 |
| 应用网络已阻断 | 重新检查节点和连接，不要绕过限制。 |
| 状态暂不可用 | 刷新并查看私有日志。应用目前无法确认状态，不会继续显示过期的成功结果。 |

连接会定期复核，因此发现上游出口变化需要一定时间。IP 地区来自外部数据库估计。应用**不能证明设备的物理位置，不能隐藏所有容器或代理特征，也不保证服务商接受账号登录**。网络控制约束的是工作环境到所选节点的路径，无法控制提供商在节点之后如何转发流量。服务商规则和账号验证仍然适用。
